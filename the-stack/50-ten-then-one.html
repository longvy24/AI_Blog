The 22-second version · Stage 4 of 5

Stage four — the procurement era, the stretch where the tooling finally got good and I learned exactly where "good" stops. The test was mundane: turn a model I had in a spreadsheet into a slide deck. I handed it to GitHub Copilot, running in VS Code, and watched it try ten times. None of the ten landed.

Here's what it actually did. Asked for a PowerPoint, Copilot wrote python-pptx — code that places every shape on the slide by coordinate. It was positioning text boxes and charts at numbers it never saw rendered, guessing at a layout it had no way to look at. Ten guesses, ten near-misses, because you cannot lay out a page you can't see.

The real reason
It's not blind.
It's the layout engine.
The Distinction

Who Computes The Layout

This is the part worth keeping. Copilot isn't bad at presentations — it's bad at .pptx specifically, and the reason is who has to compute the layout. Ask for a PowerPoint and the model has to be the layout engine: it decides, blind, that this box sits at 1.4 inches and that one won't collide with it. Ask for an HTML deck and the browser computes the layout downstream — the model writes intent, the renderer does the geometry. Ask for an analysis brief and the reader's own eye does the arranging.

Give the same tool a target where something else owns the layout and it's genuinely excellent. The fix for "AI is bad at my slides" is almost never a better prompt. It's a better format.

01 / 03Reframe
Ask For HTML, Not .pptx
"Build this deck as a single HTML file, not PowerPoint. One section per slide."
The whole fix in one line. HTML hands the geometry to the browser, so the model stops guessing coordinates and starts writing structure — the thing it's actually good at. You also get live charts and real data that .pptx can't touch.
02 / 03Delegate
Put A Renderer Downstream
"Output in a format something else lays out: HTML, Markdown, a table."
The general version of the rule. Any time the output is arranged by a downstream renderer — a browser, a Markdown viewer, a human reader — you've moved the layout off the model and onto something that's genuinely good at it.
03 / 03Choose
Pick A Tool With An Opinion
"Before you build this, tell me what you'd change about the request."
The other half of what I saw. Claude Code took a single attempt at the same deck — because it had an opinion about the request instead of just executing it. A tool that pushes back catches the bad idea before it costs you ten tries.
// Disclosure

Weigh this fairly: Claude Code built this channel, its videos, and this very blog post. So when I say it took one attempt where another tool took ten, I have an obvious bias, and you should read the head-to-head with that in mind. The technical point underneath — that .pptx forces the model to be the layout engine and HTML doesn't — holds no matter which tool you prefer.
